# 文档规则

## 读者与职责

`AGENTS.md` 面向 AI，负责开发约束和任务读取路由。`README.md` 是面向使用者的交付产物，说明能力、安装、配置和使用结果，排除在 AI 开发规则来源之外。实现变化时仍需维护 README 及相关操作指南的准确性。

| 位置                                 | 主要职责                                 |
| ------------------------------------ | ---------------------------------------- |
| docs/00-governance                   | 提交、PR、文档与协作规则                 |
| docs/10-requirements/REQUIREMENTS.md | 需求和验收条件                           |
| docs/20-design/DESIGN.md             | 当前架构、权限与生命周期、验收证据及缺口 |
| README.md                            | 对外能力概览、快速部署和阅读导航         |
| docs/30-guides                       | 面向使用者的部署、接入与验证操作说明     |
| AGENTS.md                            | AI 开发路由和必要协作约束                |

README 以人类读者为中心，优先清晰、简单和可操作；允许与 AGENTS、需求、设计或指南重复必要的信息，不因去重而要求读者来回跳转。内容过长时按使用任务拆分，README 保留理解项目和开始使用所需的信息。

AGENTS 以机器执行为中心，要求准确、无冗余；只保留开发约束、关键边界和按任务读取的路由，不复制可通过明确引用获取的长篇说明。README 与操作指南不作为机器开发规则的来源。

## 命名与证据

文档文件名使用大写英文和连字符。只创建当前需要的文档，不保留重复的审计报告、过程记录和空模板。

接口和运行行为按实际导出、锁定版本源码与可执行测试核对。规则变更按对应治理文档维护，需求调整按已确认范围维护。发现冲突时明确其来源并修正对应权威文件。

设计说明包含关联需求、职责、数据流、状态转换、失败处理和验证边界。数据流使用 Mermaid 时序图或流程图。验收记录区分本机契约、真实环境和未覆盖项。真实服务器、用户、凭据与机器路径只保存在本地 .env。

## 同步与清理

变更行为时检查需求、设计和测试。改变安装、配置或使用方式时同步 README 及相关操作指南；改变开发约束或读取路由时同步 AGENTS 和治理规则。迁移文档时更新所有引用并检查相对链接。

测试入口位于 tests 的能力目录和 e2e，fixtures 按能力目录提供 .mjs 接口。测试数据和可复跑夹具放入对应能力目录。原始审计、日志、安装依赖和临时产物放入 Git 忽略的 runtime，完成后按引用和恢复需要清理。保留仍被实际测试入口引用的夹具。
