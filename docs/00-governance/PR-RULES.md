# PR 规则

提交与标题遵循 [COMMIT-RULES.md](COMMIT-RULES.md)。Git 授权边界由 [AGENTS.md](../../AGENTS.md) 路由。

## 分支与范围

分支使用 `codex/` 前缀和简短英文主题。每个 PR 围绕一个可验证目标。可独立回退的行为分开评审，跨能力域的原子变更应解释原因。

用户授权创建 PR 后，使用仓库 [PR 模板](../../.github/pull_request_template.md)，说明最终行为、验证和缺口。Draft PR 同样记录实际完成范围。

## 内容与评审

PR 描述包含需求或问题、行为变更、验证命令与结果、未覆盖条件、配置或接口影响，以及文档同步情况。证据区分本机契约、真实远端和生产部署，使用匿名环境描述。

审查完整 PR 差异，关注目标与执行环境一致性、权限、取消、部分失败与不确定结果。反馈应包含触发条件与可观察影响。修正后重跑受影响检查。

## 合并

只有用户明确要求时才合并。合并前核对审查结果、检查状态和目标分支。默认保留有意义的提交历史，用户另有要求时按其指示执行。
