# 提交规则

## 授权与边界

只有用户明确要求提交时才暂存并提交。提交、推送、创建 PR 和合并分别取得授权。工作区中的既有改动按归属保留，暂存前检查完整差异。

一个提交表达一个可审查、可验证和可回退的工程判断。相同判断所需的源码、测试、配置和文档一并提交，独立判断分开提交。

## 标题

使用 `Type(project): 中文工程判断`。Type 可为 Feat、Fix、Docs、Test、Refactor、CI。

| project   | 适用范围                                             |
| --------- | ---------------------------------------------------- |
| repo      | 仓库治理、共享配置、CI、开发设施与对外文档           |
| openshell | OpenShell 连接、权限包装、普通进程执行及其测试和设计 |

按主要行为的权威来源选择 project，跨域影响写入正文。标题应说明结果，正文记录必要的原因和验证。

## 提交前检查

检查实际暂存差异和敏感信息。根据影响运行 `pnpm check`、`pnpm test` 或远端验收，并同步对应文档。执行 `git diff --cached --check`，确认暂存区仅包含授权范围内的文件。`.env`、runtime 和本地 IDE 文件由 Git 忽略。
